# 学生训练报告 V2 实现说明

## 一、产品目标

学生训练报告不是系统能力清单，而是下一轮训练的行动入口。学生应在两分钟内回答四个问题：

1. 本轮结果如何；
2. 哪些具体动作影响了结果；
3. 这些动作为什么重要；
4. 下一轮在什么时机做什么，以及怎样算完成。

学生主报告因此只保留“本轮结果、关键决策复盘、下一轮训练处方、跨轮变化”四类内容。评分维度、完整对话、RAG 来源和审计记录仍然保留，但统一进入默认折叠的证据明细。

## 二、职责边界

| 模块 | 新职责 | 不再承担的职责 |
|---|---|---|
| 结构化评分与 Deep Report | 生成诊断对照、任务完成度、证据链断点、顺序问题、人文沟通事件和训练目标 | 不再作为学生端独立长模块重复展示 |
| TeacherAgent | 根据可信证据提出学生思维假设，并生成中文教师判断 | 不修改病例事实、标准诊断、Rubric 或评分 |
| Student Training Report V2 | 将评分事实、教师判断和训练目标收敛为最多 3 个关键决策与 3 个训练动作 | 不重新评分，不新增病例事实 |
| Personal Skill | 记录通过审批与回归门禁的长期教学策略 | 不把候选 ID、内部策略或审批技术字段直接展示给学生 |

数据流如下：

```text
训练轨迹与评分事实
  → Deep Report 结构化证据包
  → TeacherAgent 教学解释
  → Student Training Report V2 组合与学生可见字段门禁
  → 学生报告四模块
```

## 三、V2 数据合同

`student_training_report` 包含：

- `outcome`：得分、诊断判断、安全和沟通结论；
- `decision_replays`：最多 3 个关键时刻，每个都有观察证据、教师判断、影响和正确下一步；
- `training_prescriptions`：最多 3 个训练目标，每个都有触发条件、动作和成功标志；
- `longitudinal_summary`：区分首次出现、连续出现、改善后再现和本轮暂未再现；
- `personal_memory_summary`：只用一句中文说明系统记住的训练重点和启用边界。

学生可见字段会拒绝 UUID、`snake_case` 内部标签和纯英文状态值。历史报告或旧接口缺少 V2 字段时，前端使用同样的中文门禁生成兼容结果，不把原始技术字段回退到页面。

## 四、高分学生保护

没有评分缺口、沟通漏项、证据断点或顺序问题时，系统不得为了填满卡片而生成“主要问题”。此时：

- 关键决策只展示有证据的有效做法；
- 下一轮目标改为迁移训练；
- 成功标准要求在新病例中独立复现，并保持安全和沟通质量。

## 五、真实场景验收

自动化真实场景测试覆盖实际阑尾炎病例及其结构化评分数据：

1. 诊断正确但证据链不足；
2. 合理但错误的鉴别诊断；
3. 查体前未取得同意的安全顺序问题；
4. 患者表达焦虑后未及时回应；
5. 高分学生不被编造弱点；
6. 问题连续出现和改善后再现。

共同门禁：主报告不显示 UUID 或内部枚举；每项问题有观察证据；训练动作不超过 3 条且包含触发条件和成功标准；高分场景只强化和迁移已有能力。
