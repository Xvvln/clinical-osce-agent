# RAG 真实场景验收记录

## 验收目标

本轮不是只验证函数返回成功，而是模拟学生、教师和新部署环境中会真实发生的知识库操作，检查“找得到、拿不到越权内容、坏资料进不去、外部模型不可用仍可用”。

## 场景一：五类学生口语求助

在全新隔离知识库中，关闭 embedding 和 rerank，只保留本地 BM25，分别模拟：

- “肚脐周围痛后来跑到右下腹，还恶心，我接着该问什么？”
- “胸口像石头压着还往左肩窜，出了一身汗，病史还要问什么？”
- “走路憋气，平躺更喘，半夜会憋醒，脚也肿了，该怎么追问？”
- “最近心慌手抖、怕热还变瘦，问诊要补哪些？”
- “发烧咳黄痰，一咳嗽右胸就疼，我还应该追问什么？”

结果：五条均命中对应病例的 `history_taking` Coach 知识；返回项只属于当前病例或全局知识，均为 `pre_submit_safe`，文本中不含该病例主诊断名。

## 场景二：诊断提交后的复盘

分别用五病例的症状、体征和检查证据请求 Reflection 复盘。结果：五条均命中对应病例的提交后 Reflection 知识，允许显示主诊断和完整证据链；没有混入其他病例内容。

这说明系统不是永久隐藏诊断内容，而是按教学阶段控制：提交前帮助学生组织动作，提交后帮助学生核对推理。

## 场景三：教师上传高风险资料

模拟教师上传以下内容：

> 最终诊断为急性阑尾炎，建议立即给予抗生素治疗。本段只用于训练后复盘。

系统同时标记 `diagnosis_answer_content` 和 `treatment_or_dose_content`，初始状态为 `pending_review`。尝试把它作为提交前 Coach 内容批准时返回 409；学生提交前检索不到该片段，也看不到其中的诊断或抗生素内容。

把同一片段改为 `post_submit_review`、限制为 Reflection、绑定反馈阶段并人工批准后，提交后复盘可以检索到它。该场景验证的是“用途修正后审核放行”，不是忽略风险标记。

## 场景四：真实中文 OCR

使用系统中文字体生成 1600 × 520 的四行教学卡，直接调用 RapidOCR + ONNX Runtime；随后把同一图片保存为无文本层 PDF，走 PDF 渲染与 OCR 完整链路。

结果：

- 图片识别 4 行，平均置信度 `0.9991`；
- 四行中文与原始教学卡一致；
- 扫描 PDF 生成 1 个 chunk；
- chunk 类别为 `OCRText`，策略为 `local_pdf_page_window`；
- 没有借助外部 OCR API。

## 场景五：30 条检索基准与冷启动

使用全新 SQLite 路径，不预先打开管理端。检索首次运行会自动初始化并装载 26 条默认知识。关闭 embedding 与 rerank 后执行全部 30 条口语 gold query：

| 指标 | 结果 |
| --- | ---: |
| Recall@3 | 0.7250 |
| Recall@5 | 0.7972 |
| MRR@5 | 0.7478 |
| nDCG@5 | 0.6967 |
| Source coverage | 0.7647 |
| Hit@5 | 1.0000 |
| 零命中 | 0 |

Hit@5 为 1 表示每条查询的前五项至少有一个标注相关材料；Recall@5 不是 1，表示部分查询还有其他相关材料未进入前五。二者不能混写成“召回完全正确”。

## 回归结果

- 现实语境专项：`11 passed`；
- 后端全量：`1175 passed, 2 warnings`；
- 学生端：`138 passed`，TypeScript 类型检查和 production build 通过；
- 管理端：`26 passed`，TypeScript 类型检查和 production build 通过；
- JSON 与 Git whitespace 校验通过。

## 未包含在本轮结论中的事项

- 正式医学教师对 26 条默认知识逐条签字审核；
- 外部 Vertex embedding 与 DashScope rerank 的实时联网 SLA；
- 多机并发、海量文档、异步重建和生产监控；
- 真实患者诊疗有效性。

这些是课程或生产部署的后续验证边界，不影响当前比赛演示中的五病例教学知识、OCR、审核、受控检索和来源追溯闭环。
