# RAG 文档本地解析实现说明

## 目标

教师上传教学资料时，不再让 PDF、DOCX、PPTX 和 HTML 的基本解析依赖 Unstructured 的可选格式模块。常见格式先走项目已有的轻量依赖，其他格式仍可使用 Unstructured 兜底。

## 已实现格式

| 格式 | 本地解析器 | 保留信息 |
| --- | --- | --- |
| MD / Markdown | 项目内 Markdown 解析 | 标题、章节、段落 |
| TXT / TEXT / CSV | 项目内文本解析 | 段落 |
| HTML / HTM | 标准库 `HTMLParser` | 标题、正文、列表；忽略脚本和样式 |
| PDF | `pypdf` + `pypdfium2` + RapidOCR | 页码、可选择文本；无有效文本层的页面自动渲染并 OCR |
| DOCX | `python-docx` + RapidOCR | 标题、段落、表格文本与内嵌图片文字 |
| PPTX | `python-pptx` + RapidOCR | 幻灯片页码、标题、正文、表格文本与图片文字 |
| PNG / JPG / WEBP / BMP / TIFF | Pillow + RapidOCR | 单图及多帧图片文字、帧顺序 |

所有格式继续使用统一的章节窗口切分、长度警告、风险标记和 `source_location` 追溯字段。OCR 产生的内容显式标记为 `OCRText`，管理端文件选择器已加入上述图片格式。含诊断答案、治疗 / 剂量或参考文献段的内容默认进入 `pending_review`；无风险标记的片段可自动准入。

## 明确边界

- OCR 默认在 API 进程内使用 ONNX Runtime 本地运行，不上传教学文档到第三方服务；单图像限制为 2400 万像素，多帧图限制 20 帧，单份 PDF 最多对 80 个无有效文本页运行 OCR。
- OCR 能识别图片中的中英文文字，但不会自动理解复杂图表、影像学图像含义或高精度版面语义。
- 文档解析成功只代表可形成候选知识片段；是否能被 Agent 读取仍受病例、可见性、角色、启用状态、审核状态和阶段范围约束。
- 训练前可见且面向生成式 Agent 的片段，如果含诊断答案或治疗 / 剂量内容，即使管理员点击批准也会被后端拒绝；需先删除风险内容或改为提交后复盘可见。

## 验证

- 单元测试覆盖 PDF 文本层、扫描 PDF OCR、直接图片 OCR、图片型 PPTX、DOCX、HTML、Markdown 和 Unstructured 兜底。
- 真实 OCR 烟测使用中文教学卡和无文本层 PDF，均成功识别并生成带页码的 `OCRText` chunk。
- 风险准入回归覆盖待审内容不入索引、训练前诊断答案不得批准、提交后复盘资料人工批准、整份文档退回和编辑后重新评估。
