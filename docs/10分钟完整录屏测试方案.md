# 临境 OSCE 智能体 10 分钟完整录屏测试方案

本文档用于在 10 分钟以内，用一个推荐病例完整展示临境 OSCE 智能体（TraceOSCE）的学生端训练闭环、教师式复盘、RAG 知识库边界、Skill 自学习闭环和管理员端审计能力。

推荐主病例：**右下腹痛教学病例（appendicitis_001）**。

选择理由：

- 病例最适合非医学评委理解：腹痛、转移、查体、血常规、超声、尿常规和鉴别诊断都直观。
- 能稳定展示“学生不是只猜诊断，而是训练临床思维链”：问诊、查体、检查、鉴别、诊断证据链。
- 能展示三档训练模式：初级点选、中级批量选择、高级自由申请。
- 能展示报告、画像、Skill、RAG 知识库、来源追溯和管理员审计，不需要额外病例切换。

## 1. 演示目标

10 分钟内让观看者看到：

1. 学生端不是普通问答页面，而是 OSCE 临床思维训练工作台。
2. 标准化病人只回答当前病例事实，不直接给标准诊断。
3. 学生可以选择训练难度，完成问诊、查体 / 检查申请、最终诊断提交。
4. 请求提示由教师智能体根据上下文、画像和 Skill Router 判断下一步，不是固定模板。
5. 高级模式可自由申请查体 / 检查；已有病例配置直接返回，未配置项目明确标记为不可用，不生成病例事实。
6. 报告不是只给分，而是给教师式复盘、素材覆盖、个人训练 Skill、结构化来源与可追溯依据。
7. 管理端能看到病例、Rubric、知识库、训练 Session、报告、Agent 轨迹、错误模式、候选 Skill、审批 Agent 和系统评测。
8. RAG 知识库只服务 Coach、复盘、Skill 生成 / 审批和学习推荐，不参与标准诊断裁判或评分决策。

## 2. 演示前准备

### 2.1 服务与账号

- 学生端：`http://localhost:3000`
- 管理端：`http://127.0.0.1:3001`
- 后端 API：`http://127.0.0.1:8000`
- 学生账号：由私有 `.env` 显式启用并单独提供
- 管理员账号：由私有 `.env` 显式启用并单独提供

Compose 和 API 默认都关闭固定演示学生与管理员且不提供默认邮箱或密码。录屏前必须完整配置两组 `ENABLED/EMAIL/PASSWORD`；演示 seed 只有在两组配置都完整的本地模式下才执行。录屏账号不得依赖仓库默认值，账号密码也不应写入公开文档或提交到 Git。

### 2.2 录屏前检查

1. 打开学生端，确认未显示管理员图谱入口。
2. 打开 API 配置弹窗，确认测试阶段采用服务端托管模型，页面不提供 API Key、请求地址、保存或连通性测试控件。
3. 打开病例选择页，确认“右下腹痛教学病例”可见，并可选择初级 / 中级 / 高级。
4. 管理端登录管理员账号，确认能读取病例台账、训练 Session、Skill 工作台和系统评测。
5. 若模型上游限速，录屏时避免重复刷新和并发提交。

### 2.3 浏览器布局建议

- 录屏分辨率建议 1920x1080。
- 学生端和管理端各开一个标签页，不要分屏同时展示，避免字太小。
- 同一浏览器中必须保留学生端 `localhost`、管理端 `127.0.0.1` 的不同 hostname；不要把学生端改成 `127.0.0.1`，否则两端 host-only 登录 Cookie 会互相覆盖。
- 浏览器缩放 90% 或 100%，以能清楚看到三栏工作台和报告目录为准。
- 提前清理不相关浏览器标签，避免录屏露出密钥或私人页面。

## 3. 10 分钟录屏主线

### 0:00-0:40 开场：项目定位与病例选择

页面：学生端病例选择页。

操作：

1. 登录学生账号。
2. 进入病例选择页。
3. 指向“右下腹痛教学病例”。
4. 展示训练难度选择，选择 **高级**。

讲解重点：

> 这是一个面向临床技能训练的 OSCE 智能体。学生不是直接问答案，而是围绕病例完成问诊、查体检查申请、诊断推理和复盘。这里选推荐病例“右下腹痛”，高级模式允许学生自由输入想申请的查体或检查。

预期结果：

- 页面只显示学生可见摘要，不显示标准诊断、Rubric、隐藏事实或管理员图谱。
- 病例卡能看到病例主题、难度、线索数量或可训练状态。

### 0:40-2:20 学生问诊：标准化病人与多意图识别

页面：学生端训练工作台。

建议输入：

```text
什么时候开始疼的？一开始哪里疼，现在哪里疼？
```

等待标准化病人回复后，再输入：

```text
怎么个痛法？有多痛？走路或者咳嗽会不会加重？
```

讲解重点：

> 标准化病人只根据病例中当前允许披露的事实回答。学生一句话问多个问题时，后端会识别多个问诊意图并更新右侧已收集线索，而不是只命中一个关键词。

观察点：

- 病人回复自然，不直接说“急性阑尾炎”。
- 回复下方的智能体流程只显示病人回复相关流程，不出现 Skill 或教学知识库检索。
- 右侧“已收集线索”自动滚动到最新命中的线索，并有短暂呼吸高亮。

可选错误输入：

```text
？
```

预期结果：

- 系统不应崩溃。
- 标准化病人或教师提示应引导学生把问题问具体。
- 无效输入不应强行检索教学知识库。

### 2:20-3:10 请求提示：教师智能体与 Skill Router

页面：学生端训练工作台。

操作：

1. 点击“请求提示”。
2. 等待过程提示出现。
3. 展开“智能体流程”。

讲解重点：

> 请求提示不是固定文案。教师智能体会看当前病例、已收集线索、训练难度、学生画像和候选 Skill 索引，再判断是否需要调用某条 Skill。空白开局时可以不调用 Skill；当学生暴露出具体问题时，才会渐进式展开相关教学策略。

预期结果：

- 过程提示卡片与病人回复卡片视觉上有区分。
- 若本轮调用了 Skill，应显示“本轮 Skill 依据”；若未调用，也应正常给下一步问诊建议。
- 提示应像老师引导学生，而不是直接给标准诊断。

### 3:10-4:20 高级模式：自由申请查体 / 检查

页面：学生端训练工作台底部申请栏。

建议输入：

```text
测量体温、检查右下腹压痛和反跳痛，申请血常规、CRP、尿常规、腹部超声
```

操作：

1. 点击“提交申请”。
2. 点击“查看申请内容”。
3. 打开返回结果。

讲解重点：

> 高级模式下学生可以自由表达想做什么检查。系统会把自由文本路由到病例已有的查体和检查项目；病例未配置的项目统一显示为“本病例暂不可用”，不会生成或写回新的病例事实，也不参与评分。

预期结果：

- 已配置项目直接返回结构化结果。
- 未配置项目显示 `unavailable`，不得出现 AI 编造的查体、检查或患者资料。
- “查看申请内容”应能看到所有已申请过的内容。
- 查体 / 检查不会直接告诉学生下一步诊断答案。

### 4:20-5:20 提交诊断：故意保留一些问题

页面：右侧栏“填写诊断”。

操作：

1. 点击右侧顶部显眼的“填写诊断”按钮。
2. 填写最终诊断和证据链，故意不要写得太完美。

建议填写：

主诊断：

```text
急性阑尾炎
```

诊断依据：

```text
患者右下腹痛，有发热，查体有右下腹压痛，血常规和超声支持急性阑尾炎。
```

鉴别诊断：

```text
需要排除胃肠炎、泌尿系结石和克罗恩病。
```

证据不足或不确定点：

```text
还需要进一步结合尿常规和腹膜刺激征判断。
```

讲解重点：

> 这里故意保留一些不完整之处，方便展示系统不是只看诊断名称是否正确，而是评价证据链、鉴别诊断和临床推理完整度。

预期结果：

- 提交诊断后会生成报告。
- 训练记录中该 session 应标记为已结束，不能继续训练，只能查看报告或删除记录。

### 5:20-6:50 学生报告：教师式复盘、素材覆盖、Skill 与来源

页面：评分报告页。

操作顺序：

1. 看“总览”和维度图表。
2. 看“教师复盘”。
3. 看“个人训练 Skill”。
4. 看“本轮结论 / 素材覆盖图谱”。
5. 展开“评分依据与来源”。

讲解重点：

> 报告不是大模型随意点评。评分由 Rubric 和结构化证据链完成；教师复盘会用老师口吻解释学生哪里没有问完整、为什么要补这些证据、下一轮应该怎么做。来源区用于答辩和审计，说明反馈和建议来自病例、Rubric、已披露事实、知识库或来源台账。

预期结果：

- 教师复盘能指出本轮具体问题，而不是只列漏项。
- 本轮结论显示“已覆盖 / 未覆盖”的素材覆盖，而不是原始字段 ID。
- 个人训练 Skill 若仍在后台生成，应显示生成中或稍后提示；若已生成，应能看到可读的训练策略摘要。
- 评分依据与来源默认折叠，展开后能看到结构化引用，不应把 RAG 说成评分裁判。

### 6:50-7:30 学习画像与训练记录

页面：学生端个人中心。

操作：

1. 打开训练记录。
2. 确认刚才 session 状态为“报告已生成 / 训练已结束”。
3. 打开学习画像。

讲解重点：

> 学生的训练不是一次性记录。系统会把报告聚合到个人画像中，形成当前薄弱项、学习路径和已启用 Skill 的使用记录。样本不足时系统会如实显示样本不足，不伪造提升。

预期结果：

- 训练记录能打开报告，已结束 session 不允许继续训练。
- 删除记录按钮为红色，并需要二次确认。
- 学习画像能看到能力维度、个人 Skill、应用次数或样本不足提示。

### 7:30-9:20 管理端：病例、知识库、训练审计、Skill 闭环

页面：管理端。

操作顺序：

1. 登录管理员账号。
2. 打开“病例与来源台账”。
3. 切到“知识库”，展示病例文档知识库或高级手工条目。
4. 打开“训练记录”，选择刚才的 Session，读取报告和日志。
5. 打开“Agent 轨迹”，展示受控话轮记忆和教师智能体决策。
6. 打开“洞察”，展示错误模式统计和来源热度。
7. 打开“Skill 工作台”，展示候选 Skill、自动应用设置、审批 Agent 修订记录。

讲解重点：

> 管理端不是只看后台数据，而是教师和答辩审计台。它能看到病例、Rubric、知识库、来源台账、训练过程、报告、错误模式和 Skill 生成 / 审批 / 应用。RAG 知识库可以由教师上传文档并切分为 chunk，供 Coach、复盘和 Skill 审批使用，但不参与标准评分。

预期结果：

- 病例台账显示中文病例名、Rubric 和来源，不以原始 ID 为主要阅读内容。
- 知识库能显示文档、chunk 数、启用状态和可使用模块。
- 训练 Session 能看到刚才学生的报告和日志。
- Agent 轨迹能看到教师提示、Skill Router 或跳过原因。
- Skill 工作台能看到候选状态、回归阻塞、审批 Agent 修改、自动应用开关和样本不足效果说明。

### 9:20-10:00 系统评测与总结

页面：管理端“系统评测”。

操作：

1. 展示最近一条系统评测。
2. 如时间允许，点击“运行系统评测”。

讲解重点：

> 系统评测用于防止能力回退，例如报告来源覆盖、解释来源覆盖、结构化追溯字段是否稳定存在。它和学生评分不同，是系统质量回归测试。

收尾话术：

> 这套系统的重点不是让大模型直接给答案，而是把标准化病人、训练工具、Rubric 评分、RAG 知识辅助、教师复盘、学生画像和 Skill 自学习闭环串起来，形成一个可演示、可测试、可追溯的临床技能训练智能体。

## 6. 10 分钟内不建议展开的内容

这些功能可以在说明书或备用录屏中展示，不建议占用主录屏时间：

- 新建账号、修改密码、完整 API 配置细节。
- 完整 JSON 导出内容。
- 大段原始日志和原始技术 ID。
- 手工导入新病例 / 新 Rubric。
- 真实密钥、服务端地址或代理地址。
- 生产部署、HTTPS、RBAC、监控告警等非核心赛道能力。

## 7. 异常与备用方案

| 异常 | 录屏处理 |
| --- | --- |
| 模型响应较慢 | 展开“智能体流程”，说明系统正在执行意图解析、病例事实匹配和教师复核；不要重复点击提交 |
| 高级申请包含未配置项目 | 展示 `unavailable`，说明活动训练严格以结构化病例配置为事实边界 |
| Skill 仍在生成中 | 展示“生成中”状态，然后切到管理端 Skill 工作台看历史候选或自动应用设置 |
| 系统评测运行超过 20 秒 | 展示最近一次评测结果，不现场等待 |
| 报告暂未刷新 | 从训练记录重新打开报告，或管理端按 session_id 读取报告 |
| 上游 API 限速 | 暂停连续请求，改展示已生成报告、管理端审计和系统评测 |

## 8. 录屏验收标准

一条合格录屏应在 10 分钟内至少出现以下画面：

1. 学生端病例选择页：推荐病例 + 难度选择。
2. 学生端训练工作台：标准化病人问答 + 已收集线索高亮。
3. 学生端请求提示：教师智能体提示或 Skill 依据。
4. 高级模式申请：自由输入查体 / 检查并查看结果。
5. 诊断提交：结构化最终诊断表单。
6. 报告页：教师复盘、素材覆盖、个人 Skill、来源追溯。
7. 学习画像或训练记录：个人闭环证据。
8. 管理端：病例 / 知识库 / 训练 Session / Agent 轨迹 / Skill 工作台至少各闪过一个关键证据。
