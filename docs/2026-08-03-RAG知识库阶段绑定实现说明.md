# RAG 知识库阶段绑定实现说明

## 目标

在既有知识库上补齐“病例 + 训练阶段 + 可见性 + Agent”四层运行时约束，不重复创建向量库或另一套医学资料。现有 5 个病例的公开医学教学种子继续直接使用，只补充其适用阶段元数据。

## 数据与管理端

- knowledge item 和文档 chunk 增加 `stage_scope`；默认值为 `['any']`，因此旧版管理员文档继续可用，不做破坏性数据迁移。
- 管理端上传文档时可以选择全部阶段，或选择病例导入、问诊、查体、辅助检查、诊断提交前、训练后复盘等具体阶段。
- 文档列表和知识片段详情展示中文阶段标签；编辑旧 chunk 时会保留其阶段范围。
- SQLite 保存结构化阶段数组；Chroma source metadata 同时保存标量化的 `case_id`、`visibility`、`allowed_agents` 和 `stage_scope`。Manifest schema 升级到 1.2，旧索引会被识别为需要重建。

## 运行时绑定

| 调用入口 | 检索阶段 |
| --- | --- |
| TeacherAgent 训练中提示 | 当前 session 阶段 |
| 高级模式 AI 查体 / 检查模拟 | 申请项目的 `physical_exam` 或 `auxiliary_test` |
| 训练后复盘 | `feedback` |
| Skill 生成 | 目标 Skill 的适用阶段 + `feedback` |
| ApprovalAgent | 候选 Skill 的适用阶段 + `feedback` |

检索先回查 SQLite，按启用状态、病例、可见性、Agent 和阶段形成安全候选引用集合，再让 Chroma 在这个集合内完成向量排序，最后按需进入 Rerank。这样不会因为全局病例、Rubric 或来源说明占据向量前排而把当前阶段的可用知识挤掉，也不会把不允许当前 Agent 读取的片段发送给外部重排服务。`any` 条目跨阶段可用；显式阶段条目只在请求阶段有交集时进入模型上下文。`history`、`auxiliary_testing` 等历史名称会归一到当前阶段名。

## 既有知识库复用

- 问诊类安全教学种子绑定病例导入 / 问诊阶段。
- 查体类种子绑定查体阶段；辅助检查类种子绑定辅助检查阶段。
- 跨阶段急腹症危险信号保留 `any`。
- 训练后复盘和 Skill 生成资料绑定诊断提交 / 复盘阶段。

这次没有把答辩通知、演讲稿或比赛 PPT 导入医学知识库；它们只用于解析器烟测，避免无关内容污染医学检索。

## 安全边界

阶段命中只是“允许进入该 Agent 的候选上下文”，不是评分证据。知识库仍不能决定病例事实披露、标准诊断、Rubric 得分或高级模式生成结果是否通过安全审批。

学生接口只返回本轮知识引用数量，不返回内部引用 ID、标题或正文；完整引用仅保留在服务端训练审计中。

## 真实场景验收

以高级阑尾炎训练为例，先完成疼痛迁移问诊并请求 Coach 提示，再申请腹部反跳痛查体并再次请求提示：

- 问诊阶段实际引用 3 条知识，阶段范围只包含 `any`、`case_intro`、`history_taking`，没有混入查体专属知识。
- 查体阶段实际引用 3 条知识，其中包含 `physical_exam` 专属条目，没有混入问诊专属知识。
- 两次提示均未显示标准诊断；学生响应只显示引用数量。
- 场景使用的临时病例和临时知识片段在验收后全部删除。
