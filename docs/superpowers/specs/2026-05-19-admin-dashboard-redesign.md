# 管理端页面重设计方案

日期：2026-05-19

## 背景

当前管理端已经覆盖管理后台需要的主要能力，但页面组织方式仍接近“所有模块铺成一条长页面”。用户进入后会同时看到模型配置、病例台账、知识库、Session、报告、日志、洞察、评测、Skill、审计等大量内容，主次不清，滚动距离长，细节区经常挤压父容器。

本次目标是保留现有功能和左侧动态导航栏，把其余区域重构为更清晰的管理员工作台：

- 一级导航保留：配置、资源、训练、洞察、评测、Skill、审计。
- 每个一级模块增加二级页面，不再把全部内容直接平铺。
- 长详情、原始 JSON、导入表单、审批细节改为抽屉或弹窗。
- 登录、登出、账号状态改为明确的账号菜单。
- 页面文案压缩到能帮助管理员操作的程度，删除重复说明和泛泛介绍。

## 当前功能审计

### 身份与状态

- 已有管理员登录弹窗。
- 演示账号默认预填：`admin-demo@example.test` / `safe-admin-password`。
- 当前页面有“管理员登录”按钮，但缺少清晰的已登录账号状态与登出入口。
- 401 / 403 会打开登录弹窗并显示错误。

### 配置与检索

- 模型/API 配置读取：`/api/admin/model-config`。
- 展示 provider、模型、认证方式、密钥状态、代理、ChromaDB manifest、索引状态。
- RAG 检索评测读取：`/api/admin/retrieval-eval`。
- 展示 Recall、MRR、nDCG、source coverage、gold query Top5 命中和边界说明。

### 资源与知识库

- 病例列表与筛选。
- 病例 raw 详情读取和病例字段编辑。
- Rubric 详情读取和评分项说明编辑。
- 病例/Rubric JSON 预检与导入。
- 数据来源登记表查看。
- RAG 知识条目查看、新增/更新。
- 文档知识库上传，支持 case/global 范围、visibility、allowed_agents、source_id、tags、enabled。
- 文档启用/停用。

### 训练证据

- Session 分页、筛选、导出。
- 输入 session_id 读取报告和训练日志。
- 报告分页、筛选、导出。
- 评分报告详情：总分、维度分、漏项、学习建议、证据覆盖、来源引用。
- 训练日志详情。
- 受控话轮记忆。
- 智能体决策轨迹。
- 反思轨迹。

### 洞察

- 错误模式统计：高频漏项、话轮模式、学习建议、来源引用。
- 教学重点模式列表与详情。

### 系统评测

- 评测批次分页、筛选。
- 运行系统评测。
- 评测图表摘要。
- 评测详情与 JSON 导出。

### Skill 闭环

- Skill 效果统计：样本不足提示、使用/未使用组描述性统计。
- 候选 Skill 列表、筛选、分页、导出。
- 从训练日志生成候选 Skill。
- Skill 自动应用开关。
- 审批 Agent 状态、修订记录、审批多轮记录。
- 候选详情：范围、应用条件、来源报告、来源会话、话轮模式、候选说明、教学策略、RAG 证据、联网核查状态、教学动作计划、禁止内容策略、回归结果、审核审计事件。
- 人工批准/拒绝候选 Skill。

### 审计

- 审计事件分页、筛选、导出。
- 事件 payload 查看。

## 设计原则

1. 管理端不是宣传页，第一屏应像工作台：状态清楚、入口明确、列表和操作优先。
2. 左侧导航只负责“去哪个工作区”，不要承担所有细节。
3. 二级页面负责“当前工作区里做什么”，用 tab/segment 控制。
4. 列表、详情、原始数据分层：列表默认展示，详情抽屉打开，原始 JSON 默认折叠。
5. 主界面只显示结论字段和必要操作；低频解释放到说明抽屉。
6. 不删除现有后端能力，不改变 API 契约。
7. 不把技术字段裸露给管理员；必要时保留在“技术细节”折叠区。
8. Skill、RAG、评测这些复杂模块要能用于答辩展示，但不能压垮日常操作视图。

## 总体布局

### 顶部栏

替代当前大块 header。

- 左侧：`临境 OSCE 管理后台`
- 中间：当前模块标题和一行状态，例如 `训练 · Session 与报告`
- 右侧：
  - 后端状态 chip：已连接 / 读取失败
  - 刷新按钮
  - 管理员账号按钮

账号按钮点击后打开悬浮菜单：

- 当前账号邮箱
- 管理员状态：已登录 / 未登录
- 重新登录
- 退出登录，红色文字和红色描边

未登录时点击受保护操作仍打开登录弹窗。

### 左侧动态导航栏

保留现有左侧动态导航能力：

- 支持折叠。
- 支持滚动定位到当前模块。
- 不使用 fixed 定位，继续使用 sticky。
- 一级模块保持：
  - 配置
  - 资源
  - 训练
  - 洞察
  - 评测
  - Skill
  - 审计

改进：

- 激活态颜色改为柔和描边和浅底，不再使用强黑色。
- 折叠态只显示短标签或图标占位。
- 每个一级项显示当前模块的关键数量，例如训练报告数、候选 Skill 数、审计事件数。
- 点击一级项后，内容区顶部显示该模块的二级菜单。

### 内容区

内容区统一为：

1. 模块标题栏：标题、关键状态、主操作。
2. 二级菜单：segment/tab，不换行，不挤压。
3. 当前二级页面主体：列表 + 详情抽屉或主从两栏。

不再保留全局五个总览卡片。需要的统计放到各模块标题栏，减少第一屏噪声。

## 一级模块与二级页面

### 配置

二级页面：

- 模型接入
- RAG 评测
- 运行边界

主界面：

- 模型接入只显示服务商、模型、认证方式、配置状态、索引状态。
- 每个 provider 的 base_url、环境变量、manifest 路径放入“连接细节”抽屉。
- RAG 评测展示五个指标和最近评测状态；gold query 命中列表放入详情抽屉。
- 运行边界用短列表说明：RAG 用于 Coach、复盘、Skill 生成/审批；不参与评分裁判。

### 资源

二级页面：

- 病例台账
- Rubric
- 知识库
- 来源
- 导入

主界面：

- 病例台账：左侧病例列表，右侧病例摘要和字段编辑入口。
- Rubric：按维度展示评分项，编辑评分项说明使用抽屉。
- 知识库：文档列表、启用状态、上传入口；上传文档使用弹窗，不在主页面铺满表单。
- 来源：来源登记表列表和详情抽屉。
- 导入：病例/Rubric JSON 预检与正式导入，独立二级页面。

### 训练

二级页面：

- Session
- 报告
- 日志
- Agent 轨迹

主界面：

- Session：分页列表、筛选、选中后右侧抽屉显示 session 基本信息和快捷操作。
- 报告：分页列表、筛选、选中后打开报告详情抽屉；保留导出。
- 日志：需要先选 session；训练日志按事件类型分组，原始 payload 默认折叠。
- Agent 轨迹：受控话轮记忆、决策轨迹、反思轨迹分为三个 tab。

### 洞察

二级页面：

- 错误模式
- 教学重点
- 来源热度

主界面：

- 错误模式展示高频漏项、话轮模式和支持报告数。
- 教学重点展示 focus pattern 列表和详情抽屉。
- 来源热度展示高频结构化来源，避免和评分报告来源链重复堆叠。

### 评测

二级页面：

- 批次
- 用例详情
- 导出

主界面：

- 批次页展示最近批次、通过率、失败数、运行评测按钮。
- 用例详情页展示选中批次的失败/通过用例，长文本折叠。
- 导出页保留评测 JSON 导出。

### Skill

二级页面：

- 候选审核
- 自动应用
- 效果统计
- 审批记录

主界面：

- 候选审核：候选列表 + 详情抽屉；批准/拒绝按钮固定在抽屉底部。
- 自动应用：开关、审批 Agent 状态、最近一次自动审批摘要。
- 效果统计：样本不足时明确显示样本要求和当前数量；不伪造提升。
- 审批记录：候选相关审计事件和审批多轮记录，默认折叠原始 payload。

### 审计

二级页面：

- 全部事件
- Skill 审核
- 管理操作

主界面：

- 审计列表默认只显示事件类型、时间、对象、操作人。
- payload 放到详情抽屉，默认折叠。

## 交互细节

### 二级菜单

- 每个一级模块内部维护当前 tab。
- 切换一级模块时默认进入该模块第一个二级页面。
- 切换二级页面不触发整页长滚动。
- 二级菜单区域固定在内容区顶部，不使用浏览器 fixed。

### 抽屉

用于：

- Provider 连接细节。
- RAG gold query 命中详情。
- 病例详情和编辑。
- Rubric item 编辑。
- 知识库上传。
- 评分报告详情。
- Session 日志事件 payload。
- Skill 候选详情和审批记录。
- 审计事件 payload。

抽屉规则：

- 右侧滑出，宽度约 520-720px。
- Esc 或点击遮罩关闭。
- 主操作固定在抽屉底部。
- 原始 JSON 默认折叠，按钮文案写明“展开原始数据”。

### 登录/登出

- 未登录：顶部账号按钮显示“登录”。
- 已登录：显示邮箱或“管理员”。
- 点击账号按钮出现菜单：
  - 当前账号
  - 刷新数据
  - 重新登录
  - 退出登录
- 退出登录后清空前端用户态并打开登录入口；如果后端已有 logout API，则调用后端；如果没有，则先清空本地状态并让下次受保护请求触发登录。

## 视觉方向

- 背景保持浅纸色，但去掉大面积装饰渐变。
- 卡片圆角控制在 8px 左右，避免过多大圆角。
- 主色仍保留棕红，但只用于主操作、激活态和关键数字。
- 低频信息使用浅灰/浅米底，不使用强对比色块。
- 表格/列表行要紧凑，默认行高适合扫描。
- 技术字段使用等宽字体，但不在主界面占大面积。
- 所有按钮文案不能换行；长文本放到详情或折叠区。

## 自查结论

- 未删除现有后台能力。
- 登录、登出、账号状态已纳入设计。
- 保留左侧动态导航栏。
- 引入二级页面，避免所有内容都成为一级长页面。
- RAG、知识库、Skill、审批 Agent、评测、训练日志、审计均有落点。
- 低频复杂内容均迁入抽屉或折叠区。
- 后续实现应优先修改测试，再改前端代码。

## 暂不处理

- 不改后端 API。
- 不改 RAG 检索逻辑。
- 不改 Skill 生成/审批业务逻辑。
- 不做生产权限系统重构。
- 不新增真实多角色权限矩阵。
