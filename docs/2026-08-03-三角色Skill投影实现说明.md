# 三角色 Skill 投影实现说明

## 目标

保留 PatientAgent、TeacherAgent 和 ApprovalAgent 三角色协同的产品亮点，同时不让“同一段 Skill 文本同时塞给三个模型”破坏事实边界或交互效果。系统在运行时根据角色构建 `skill_role_policy.v1`，不新增另一份持久化 Skill 副本。

## 角色分工

| 角色 | 输入 | 生效方式 | 不可越过的边界 |
| --- | --- | --- | --- |
| PatientAgent | 当前 enabled Skill 中的人文类型 | 转换为无 Skill ID、无原始策略的表达聚焦 | 事实仍只来自本轮 `answerable_fact_candidates`；情绪仍只来自当前状态 |
| TeacherAgent | Skill Router 本轮选中的 Skill | 使用教学目标、Coach 策略、最多三层提示、完成信号和避免事项 | 病例事实、当前提示策略和安全边界优先 |
| ApprovalAgent | 候选 Skill、禁区策略、成效指标和审批知识 | 建立角色策略检查并写入审批记录 | 质量复核或角色策略失败时，Regression Gate 必须阻断 |

## 关键实现

- `skill_role_policy_service.py` 为纯函数投影层，不读写数据库，避免引入难以清理的持久化角色引用。
- PatientAgent 的 provider payload 只增加去标识化 `role_skill_policy`，本地 Agent Turn 内存仍保留来源 Skill ID，用于教师审计。
- TeacherAgent 在 Skill Router 完成选择后才组装角色投影；空白开局或 Router 选择为空时不注入。
- ApprovalAgent 将禁区完整性和成效指标声明加入 `quality_review`，`TrainingSkillRegressionGate` 对审批阻断、质量失败和角色策略失败进行强制检查。

## 验证重点

1. 人文 Skill 能产生患者表达聚焦，临床推理 Skill 不进入 PatientAgent。
2. PatientAgent provider payload 不含 Skill ID、原始策略、Rubric 或受保护诊断。
3. TeacherAgent 只获得 Router 选中的干预，选择为空时不产生角色策略。
4. 显式弱化隐藏事实禁区或缺失成效指标的候选不能自动应用。
