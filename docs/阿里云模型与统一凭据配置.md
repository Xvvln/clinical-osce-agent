# 阿里云模型与统一凭据配置

## 目标与边界

项目默认使用阿里云百炼北京地域的 `qwen-plus`，通过
`https://dashscope.aliyuncs.com/compatible-mode/v1` 的 OpenAI-compatible
协议接入。标准化病人改写、意图识别、教师提示、语义评分、Skill
候选和报告增强继续共用现有 `OpenAICompatibleChatClient` 边界，不在各
Agent 内部散落新的 SDK 或密钥读取逻辑。该统一客户端在请求
`response_format=json_object` 时会保证系统提示明确要求输出 JSON，兼容
DashScope 对结构化输出提示词的校验，避免问诊成功但报告生成被 400 拒绝。
普通问诊仍使用 30 秒整请求预算；报告评分和后台增强需要顺序复核多个量表
边界样本，单独使用默认 90 秒、最高 300 秒的受控预算
（`OSCE_REPORT_MODEL_CALL_TIMEOUT_SECONDS`），避免把一次完整评分误按单轮对话
超时，同时继续受模型并发闸门约束。
主文本推理的单次 DashScope 传输默认最多等待 12 秒；仅在传输超时且尚未
产生业务写入时由统一客户端重试 1 次，整条普通问诊仍不能超过 30 秒。
接口层不重放创建 session、学生消息或提示请求，因此不会用重复写入掩盖
服务端失败。

本地 RAG 向量召回默认使用 `BAAI/bge-small-zh-v1.5`，不需要向境外
模型服务发送病例内容。DashScope `qwen3-rerank` 仍是可选增强，不参与
评分裁决，默认最多等待 5 秒，失败或超时后立即回退原向量顺序，不能阻塞
标准化病人和教师提示的主流程。

## 统一 Key 数据流

```text
DASHSCOPE_API_KEY（服务端）
  ├── 主文本模型：qwen-plus / compatible-mode
  ├── 语音：qwen3-asr-flash + qwen3-tts-flash
  └── 可选重排：qwen3-rerank
```

凭据优先级如下：

1. 主文本模型优先使用 `OSCE_OPENAI_API_KEY`。该项为空且目标是受信
   阿里云地址时，依次尝试 `DASHSCOPE_API_KEY` 和兼容旧配置
   `OSCE_DASHSCOPE_SPEECH_API_KEY`。
2. 语音优先使用 `OSCE_DASHSCOPE_SPEECH_API_KEY`，否则使用
   `DASHSCOPE_API_KEY`。
3. rerank 优先使用 `OSCE_DASHSCOPE_RERANK_API_KEY`，否则依次使用
   `DASHSCOPE_API_KEY` 和兼容旧的语音 Key。

后两类功能的专用 Key 是显式覆盖项，用于权限分离或经审核的自定义
网关；常规部署只需设置 `DASHSCOPE_API_KEY`。

## 受信地址规则

统一 Key 只能发送到同时满足以下条件的地址：

- HTTPS，端口为默认 443，不带 URL 用户名、密码、查询串或 fragment。
- hostname 为 `dashscope.aliyuncs.com`、其 `*.dashscope.aliyuncs.com`
  子域，或阿里云工作空间 `*.maas.aliyuncs.com` 子域。
- 后缀必须精确匹配；`dashscope.aliyuncs.com.example.org` 一类仿冒域名
  不会获得 Key。

如果 `OSCE_OPENAI_BASE_URL` 不符合上述规则，即使已配置
`DASHSCOPE_API_KEY`，主文本模型也会显示为未配置，且不会发起携带该 Key
的网络请求。自定义网关必须显式使用 `OSCE_OPENAI_API_KEY`。

## 管理端状态

`/api/admin/model-config` 会分别展示：

- 阿里云百炼 Qwen（OpenAI 兼容）主文本模型；
- DashScope 语音；
- DashScope RAG 重排。

状态仅显示是否已配置凭据及认证模式，不回显密钥、主文本模型的
私有地址或代理地址。`/ready` 只证明本地配置完整，不替代一次真实的
DashScope 出站请求验证。

阿里云要求 API Key 与地域地址匹配；北京地域地址及工作空间专属地址说明见
[Alibaba Cloud Model Studio Base URL overview](https://www.alibabacloud.com/help/en/model-studio/base-url)。
