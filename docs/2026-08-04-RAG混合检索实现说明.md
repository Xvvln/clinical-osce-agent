# RAG 混合检索实现说明

## 目标

让学生使用“憋气、心慌、脚肿、B 超、心棗”等真实口语时仍能检索到当前病例的安全教学资料，并在 embedding 未配置、临时超额或调用失败时保留可用的本地检索能力。本次不替换现有 ChromaDB，而是在同一受控候选集上增加词法召回和融合排序。

## 检索链路

1. 从当前知识库取得已启用、已批准的片段；Agent 调用时再按病例、阶段、可见性和角色生成允许引用集。
2. 对原始查询做可解释、有长度上限的医学同义词扩展；原始查询始终保留在首部。
3. ChromaDB 使用扩展查询做持久向量召回；当 Chroma 不可用但 embedding 仍可用时，回退进程内余弦相似度。
4. 同一安全候选集同时运行 BM25，中文使用原词与 2/3 字 n-gram，英文保留单词 token。
5. 使用 RRF（Reciprocal Rank Fusion，倒数排名融合）合并向量与词法结果；可选 `qwen3-rerank` 只对融合后的安全候选进行最终重排。
6. 返回值保留 `retrieval_methods`、`vector_score` 和 `lexical_score`，检索评测记录扩展查询与 Top-5 方法轨迹。

## 降级与一致性

- 没有 embedding client 时，直接在安全候选集上返回 BM25 结果。
- 所有 embedding client 都失败时，回退 BM25；显式的 provider 超时 / 限流策略异常仍按原有 fail-fast 边界向上传递。
- Chroma collection 数量必须与当前来源数量精确一致，不再把“只多不少”判为健康。
- 向量结果会再与当前有效引用集取交集；即使索引因为异常保留了旧 chunk，已删除、已禁用或未批准内容也不会被返回。
- 词法召回不扩大权限；`allowed_references` 为空集时直接空召回。

## 评测

管理端检索评测在 Recall@3 / Recall@5 / MRR@5 / nDCG@5 / source coverage 外增加：

- `Hit@5`：至少命中一个预期引用的查询比例。
- `zero_hit_query_count`：Top-5 中一个预期引用都没有的查询数。
- `expanded_query`：用于复核口语扩展是否合理。
- `retrieved_items`：保留每个结果的融合分数和召回方法。

这些指标衡量学习材料召回，不是诊断正确率、Rubric 评分证据或医学教师审核。
