# 功能对齐真实场景验收记录

## 验收目标

用学生、教师和评委真正会操作的场景，验证网页 PPT 中四项核心表述：高级模式的 AI 检查结果、文本/语音模式、三角色 Skill 分工和按训练阶段约束的知识库。

## 场景一：学生申请病例未预配置的心电图

**现实情境**：学生在高级阑尾炎训练中申请“心电图”，而病例数据没有预写该结果。

**实际链路**：系统先组装去标识化病例表现、已配置检查结果和允许的教学知识，再调用大模型生成。一致性审批节点可批准、修订或阻断；无法安全生成时关闭该结果，不用模板冒充病例事实。

**实测结果**：

- 返回状态为 `ai_simulated_for_training`，`generated_by_ai=true`。
- 结果经一致性节点修订为保守表达，不生成病例不支持的急性精确异常。
- `scoring_eligible=false`，页面标明“训练参考，不进入评分”。
- 同一请求再次发起时复用已持久化的审批结果，避免同一场训练内前后矛盾。

**结论**：已实现，但它是受约束的教学模拟，不是真实医疗检查，也不应进入 OSCE 客观评分。

## 场景二：答辩时在文本与语音模式之间切换

**现实情境**：现场环境可能不适合自动播音，也可能需要展示模拟患者的语音交互。

**实测结果**：

- 文本模式发送问题后，页面正常显示患者回答，后端没有发起 `/api/audio/speech` 请求。
- 切换到语音模式后，下一条患者回答自动请求 TTS 并播放，请求返回 HTTP 200。
- 切回文本模式后，历史患者回答仍可点击手动播放，完成后页面返回“患者语音播放完毕”。
- 浏览器控制台无 error 级日志。

**结论**：已实现。自动播放仍受浏览器媒体权限和设备音量影响，所以保留手动播放作为可见回退路径。

## 场景三：问诊知识不应污染查体阶段

**现实情境**：教师分别上传只适用于问诊和只适用于查体的知识。学生先请求问诊提示，再进入查体并请求提示。

**实测结果**：

- 问诊轮次的内部审计引用只包含 `any` 或 `case_intro/history_taking` 阶段的知识，查体专用条目被排除。
- 查体轮次可命中 `physical_exam` 条目，问诊专用条目被排除。
- 两次教学提示都没有透露保护诊断。
- 学生端公开载荷只暴露 `knowledge_reference_count`，不暴露知识 ID、原文或检索上下文。
- 检索先从 SQLite 按启用状态、病例、可见性、角色和阶段生成安全候选集，再进入 Chroma 向量检索和 Rerank；不先把未授权片段送入外部重排。

**结论**：已实现。知识文档可解析 MD、TXT、CSV、HTML、PDF、DOCX 和 PPTX 中的可提取文字；扫描图像和纯图型文档暂无 OCR，不应对外宣称已支持。

## 场景四：焦虑患者与学生的推理偏差同时出现

**现实情境**：患者说“我是不是很严重”，学生没有回应焦虑，同时在后续诊断表达中没有整理支持和排除证据。当前 Skill 同时包含“患者情绪回应”和“证据链训练”。

**自动化场景结果**：

- PatientAgent 只获得无事实的人文表达聚焦，不获得“整理支持与排除证据”等教学策略，也不会因 Skill 新增诊断事实。
- TeacherAgent 只获得 Skill Router 本轮选中的“证据链训练”干预，不获得未选中的患者情绪策略。
- 尝试把 `forbid_hidden_facts` 从 `true` 弱化为 `false` 时，ApprovalAgent 的角色策略检查失败，候选 Skill 不得自动应用。

**结论**：已实现。项目亮点是三个角色对同一训练问题各负其责，而不是把同一段 Skill 原文无差别地发给三个角色。

## 场景五：恶意候选经过审批后进入下一轮训练

**现实情境**：同一学生连续两轮低质量完成阑尾炎训练。候选生成器随后错误写入标准诊断、完整隐藏病史、具体药名和剂量；审批知识库同时存在一条当前角色可读的教学规范，以及一条仅评分角色可读的秘密答案。教师采用默认人工审批，批准通过后再开始第三轮训练。

**真实 HTTP 闭环结果**：

- 前两轮通过学生登录、创建会话、提交低质量诊断和生成正式报告，系统据两份真实报告聚合候选，不手工伪造候选的来源统计。
- ApprovalAgent 保持病例、阶段、触发项、来源统计和来源引用逐字段不变，只重写教学正文、分层提示、教学 SOP 和完成标志。
- 候选详情与 enabled Skill 均不再包含标准诊断、鉴别诊断名称、完整隐藏病史、药名、`500mg` 或 `q8h`；管理端根据 Rubric ID 补充的可读标签也不会把答案二次带回。
- RAG 只返回允许 `skill_approval` 角色读取的 `post_submit_review` 条目，`scoring_only` 秘密答案没有进入审批上下文；审批记录保存命中引用。
- 回归门禁实际执行 1 个病例并通过。人工批准后，Skill 在第三轮空白开局和首次进展时保持静默，直到同类缺口再次出现才进入提示链。
- 学生画像记录该 Skill 已启用、已应用但样本仍不足；管理端审计依次保留“候选生成、Agent 审批、人工批准”，训练事件另有 `training_skill_applied` 和 Agent 决策轨迹。

**阻断对照**：角色禁区被弱化、病例上下文冲突、缺少真实 ApprovalAgent 证明、回归失败或直接绕过审批写入 Skill 库时，激活门禁均 fail-closed，不进入训练。

**结论**：审批智能体的候选净化、知识权限、结构重建、回归、人工 / 自动应用、运行时触发和审计链已经贯通。这里的“通过”表示既定安全规则和回归场景全部满足，不代表模型对所有未来病例都天然正确；新病例和新策略仍需教师抽检。
